# HyperID-KE — Project Memory / Context Export
Updated: 13 August 2026

## 1. Project objective

HyperID-KE is a dog breed/phenotype identification system combining:
- CLIP visual embeddings
- A multi-task phenotype prediction network
- An OWL/RDF ontology
- SPARQL/trait-overlap reasoning

Core intended idea:
Image → CLIP embedding → six phenotype predictions → ontology reasoning → ranked breed/phenotype candidates.

The project explicitly aims to handle mixed/local phenotypes to some extent, rather than being only a conventional closed-set breed classifier.

Six core phenotype dimensions:
1. EarShape
2. CoatType
3. CoatPattern
4. SizeClass
5. SnoutLength
6. TailCarriage

## 2. Original Oxford-IIIT Pet pipeline

Training/evaluation initially used a 13-breed subset of Oxford-IIIT Pet.

The phenotype model architecture established during the project:
- Frozen CLIP image encoder
- 512-dimensional CLIP image embedding
- Shared hidden/trunk layer: 512 → 256
- Six classification heads, one per phenotype dimension

Important clarification:
The six-head model was NOT trained with random phenotype labels.
The Oxford training labels were generated by assigning each breed a six-trait phenotype profile from the ontology, then using that profile as weak supervision for images of that breed.

Therefore:
If the ontology contains a wrong breed→trait mapping, the model can systematically learn that wrong mapping.

## 3. Plain CLIP baseline

A plain zero-shot CLIP baseline was implemented.

It does NOT require training a new model. It compares an image embedding against text prompts such as breed names and ranks the similarity scores.

Important distinction:
This is a zero-shot baseline, not a model we trained ourselves.

On one Boxer image, plain CLIP produced:
1. Staffordshire Bull Terrier — 70.46%
2. Boxer — 19.55%
3. Saint Bernard — 7.77%

Full Oxford evaluation:
- Images: 1,300
- Plain CLIP Top-1: 38.92%
- Plain CLIP Top-3: 45.38%

## 4. Grounded CLIP + phenotype + ontology system

The complete grounded pipeline was implemented:
CLIP → phenotype prediction → ontology trait matching/reasoning.

After fixing the ontology ranking implementation and the model input dimension mismatch, the system produced:

Full Oxford sanity evaluation:
- Images: 1,300
- Grounded Top-1: 91.92%
- Grounded Top-3: 99.92%

Earlier 130-image sanity run:
- Baseline Top-1: 42.31%
- Baseline Top-3: 46.15%
- Grounded Top-1: 92.31%
- Grounded Top-3: 100.00%

This established that the grounded pipeline can perform extremely well on the Oxford-style in-distribution evaluation.

Important caution:
These results do NOT by themselves demonstrate mixed-breed/generalization performance because the phenotype labels were derived from breed-level ontology profiles and the evaluation images come from the same Oxford breed universe.

## 5. Technical bugs already encountered and fixed

### Missing rank_breeds
`hyperid_oxford_eval.py` initially imported `rank_breeds` from `hyperid_reasoning.py`, but that function did not exist.

This was corrected.

### 512 vs 768 model mismatch
The trained checkpoint expected:
- input: 512

An evaluation script temporarily constructed:
- input: 768

This caused:
`size mismatch for trunk.0.weight`

The correct architecture is:
CLIP projected image embedding = 512 → model.

### Transformers CLIP output issue
`clip.get_image_features()` in the installed Transformers version returned a model output object rather than the expected tensor.

The cross-check script was corrected to explicitly use:
vision model → pooler output → CLIP visual projection → 512-D embedding.

### CUDA device-side assertion
The CNN training script initially failed with:
`Assertion t >= 0 && t < n_classes failed`

Cause: class-index mismatch in the training labels.

This was fixed in the complete CNN script.

CUDA “poisoning” clarification:
A CUDA device-side assertion can leave the CUDA context in a failed state for the current Python process. Restarting the Python process clears that state; it does NOT mean the GPU/model has been permanently damaged.

## 6. CNN baseline

A conventional ResNet-18 CNN classifier was trained on the same Oxford subset:
- 13 breeds
- 1,300 images
- Train: 1,040
- Test: 260
- GPU: NVIDIA RTX 3060

Final CNN result:
- Top-1: 94.62%
- Top-3: 99.62%

This is currently stronger than the grounded system on the Oxford closed-set Top-1 metric:
- CNN: 94.62%
- Grounded: 91.92%

However, the research question is not simply “which classifier gets the highest closed-set Oxford accuracy?”
The grounded system is intended to provide interpretable phenotype reasoning and a route toward mixed/local phenotype handling.

## 7. Mixed-breed/local phenotype problem

The project originally intended to support mixed breeds/local phenotypes.

Practical problem:
Direct collection of enough high-quality mixed-breed images in Bangladesh is difficult because:
- local mixed breeds are relatively rare in usable quantities
- logistics/time are limited
- collected images have inconsistent quality
- individual mixed dogs exhibit different combinations of traits

The initial idea considered two local mixed groups:
- German Shepherd–Deshi mix
- Spitz–Deshi mix

A collection spreadsheet/template was prepared around the six phenotype dimensions to make later ontology mapping easier.

## 8. Mixed-breed testing exposed weaknesses

Manual phenotype profiles for collected/local mixed dogs often varied substantially from image to image.

A cross-check script was created to compare:
- manually proposed phenotype profile
- trained neural phenotype prediction

Example manual-vs-model result for a German Shepherd–Deshi-type image:
- EarShape: expected ErectEars, model FloppyEars → DIFFER
- CoatType: expected ShortCoat, model ShortCoat → MATCH
- CoatPattern: expected PatchedColor, model Spotted → DIFFER
- SizeClass: expected LargeSize, model LargeSize → MATCH
- SnoutLength: expected LongSnout, model LongSnout → MATCH
- TailCarriage: expected StraightTail, model CurledTail → DIFFER
- Agreement: 3/6

This showed that the source mixed-breed image collection was not sufficiently consistent for blindly treating manual labels as ground truth.

## 9. CLIP phenotype ensemble experiment

Because the trained phenotype network was biased by Oxford-derived weak labels, an ensemble cross-check was implemented.

It combines:
- existing trained neural phenotype model
- frozen CLIP image↔phenotype text scoring

Default:
- CLIP weight = 0.65
- neural model weight = 0.35

The purpose is to see whether CLIP's direct visual evidence can correct systematic phenotype errors without immediately retraining the model.

### Example: problematic mixed-breed image

Neural model:
- EarShape: FloppyEars 90.45%
- CoatType: ShortCoat 98.50%
- CoatPattern: Spotted 98.72%
- SizeClass: LargeSize 83.01%
- SnoutLength: LongSnout 96.66%
- TailCarriage: CurledTail 58.32%

CLIP phenotype scorer:
- EarShape: ErectEars 56.69%
- CoatType: MediumCoat 55.13%
- CoatPattern: Spotted 46.27%
- SizeClass: LargeSize 33.91%
- SnoutLength: MediumSnout 69.37%
- TailCarriage: StraightTail 36.78%

Combined:
- EarShape: ErectEars 60.57%
- CoatType: ShortCoat 68.58%
- CoatPattern: Spotted 83.85%
- SizeClass: LargeSize 73.76%
- SnoutLength: MediumSnout 46.81%, LongSnout 44.72%
- TailCarriage: StraightTail 73.13%

Interpretation:
The ensemble corrected EarShape and TailCarriage substantially, but CoatPattern remained problematic. This suggests the approach is worth investigating, but not yet a final solution.

## 11. Current ontology concern

The original ontology is breed-level weak supervision.

The key risk is NOT that the labels were random.
The key risk is that some breed→phenotype assignments may be inaccurate, oversimplified, or internally inconsistent.

Example discovered during inspection:
Yorkshire Terrier was mapped as:
- ErectEars
- LongCoat
- SolidColor
- ToySize
- MediumSnout
- StraightTail

The Yorkshire description references a blue-and-tan coat, while `SolidColor` is too coarse/inconsistent with that description.

The ontology also uses functional trait properties, effectively forcing one value for each trait dimension per breed. Real breeds can exhibit variation.

Therefore, the current ontology needs an audit before treating its labels as authoritative ground truth.

## 13. Stanford Dogs idea under consideration

A possible clean restart was discussed using the Stanford Dogs Dataset:
- 120 pure breeds
- 20,580 images
- breed labels
- bounding boxes

Proposed use:
Stanford would NOT directly provide mixed-breed labels.
Instead, create breed-level phenotype profiles for the 120 breeds, use those as weak labels, train the six phenotype heads, and use ontology reasoning for mixed/OOD images.

Potential pipeline:

Stanford Dogs
→ 120 breed profiles
→ six-trait mapping
→ weak phenotype labels
→ train six-head model
→ CLIP phenotype prediction
→ updated TTL
→ ontology reasoning
→ mixed-breed/OOD testing

Important caveat:
The Stanford dataset does not directly provide the six phenotype labels. A breed→phenotype mapping must be created, and that mapping itself must be carefully verified.

## 14. Possible plans currently in consideration

### Plan A — Audit existing Oxford project first
1. Audit all 13 Oxford breed profiles in the TTL.
2. Fact-check the six trait values.
3. Correct inconsistent/coarse mappings.
4. Identify breed collisions such as Samoyed/Yorkshire.
5. Retrain the six-head phenotype model using corrected weak labels.
6. Re-run Oxford evaluation.
7. Re-test mixed/OOD images.

Advantages:
- preserves current work
- quickest route to diagnosing the current problem
- establishes whether ontology quality caused the observed failures

### Plan B — Full Stanford restart
1. Use Stanford Dogs only.
2. Define a clean six-trait vocabulary based on what the dataset can support.
3. Create verified phenotype profiles for all 120 breeds.
4. Generate weak labels automatically from breed profiles.
5. Train a new six-head phenotype model.
6. Build a matching TTL from the same verified mapping.
7. Evaluate on Stanford.
8. Test genuinely OOD mixed-breed images.

Advantages:
- much larger and more diverse pure-breed training set
- cleaner experimental story if rebuilt consistently

Risk:
- the breed→phenotype mapping remains the critical source of weak-label noise.

### Plan C — Hybrid/ensemble approach
Continue using:
- trained phenotype network
- frozen CLIP phenotype text scoring
- probability-based ontology reasoning

Instead of hard top-1 trait decisions, retain soft probabilities and use weighted trait overlap.

This may be particularly useful for mixed breeds because a mixed dog can genuinely exhibit ambiguous/intermediate phenotype evidence.

## 15. Most important immediate recommendation

Before making a major restart, perform the **13-breed Oxford TTL audit**.

Reason:
We now know the original model was trained from the TTL's breed-level weak labels. Therefore, checking whether those labels are correct is the fastest way to determine whether the current phenotype failures are caused by:
- bad ontology mappings,
- overly coarse trait categories,
- model limitations,
- or the inherent difficulty of mixed-breed visual phenotypes.

Do not treat the current mixed-breed predictions as proof that the whole architecture has failed.

## 16. Paper/evaluation framing

The project should preserve separate comparisons:
1. Plain zero-shot CLIP
2. Conventional CNN classifier
3. Grounded CLIP + phenotype model + ontology reasoning
4. Potentially the ensemble variant

The central contribution is not simply maximizing closed-set breed accuracy. The intended contribution is the use of interpretable phenotype extraction plus ontology-based reasoning to support breed identification and mixed/local phenotype handling.

The current 94.62% CNN result is therefore a useful conventional baseline rather than evidence that the grounded approach is useless.
